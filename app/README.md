# Health Insurance Cross-Sell Model Demo

Kaggle "Health Insurance Cross Sell Prediction" dataset: predicting whether an existing health insurance customer (`Response`) is interested in also buying vehicle insurance. This folder holds the small educational Streamlit application around the tuned gradient-boosting pipeline from `notebook/health_insurance_model.ipynb`.

The project follows the same four-notebook structure as the breast-cancer lab (`D:\Sample Project\breast-cancer-lab`): **ETL → EDA → statistical analysis → model → app**, with the database as the single source of truth for every notebook after the ETL.

## Project structure

```
│   ├── requirements.txt

│   ├── test.csv                127,037 unlabeled rows (Kaggle submission set)

    ├── eda_health_insurance.ipynb              2. exploratory analysis from the database
    ├── stats_analysis_health_insurance.ipynb   3. hypothesis tests, effect sizes, confidence intervals
    └── health_insurance_model.ipynb            4. trains, tunes, evaluates, exports the model
```

## Why Streamlit?

Streamlit is lighter than Django for a single-page data application: it needs no URL routing, templates, migrations, or user-account layer. Use Django later if the project grows into a multi-user system with authentication, saved leads, audit logs, APIs, or administration.

## Setup

From the project root, with the `.venv` activated (or using `.venv\Scripts\python.exe` directly):

```powershell
python -m pip install -r app/requirements.txt
```

Packages install into `.venv` on D: rather than the system Python, because C: is nearly out of space. Run the notebooks with `.venv`'s kernel ("Health Insurance (.venv)").

## Database

`notebook/health_insurance_etl.ipynb` loads `train.csv` into a local MySQL/MariaDB database (`health_insurance_db`, table `customers`) via XAMPP. Start MySQL in the XAMPP Control Panel first. Default credentials are `root` with no password; change `DB_USER`/`DB_PASSWORD` at the top of each notebook if yours differ. The notebook is idempotent: re-running it refreshes the same table and never creates a duplicate database.

The EDA, statistics and model notebooks all read from that table, not from the CSV.

## Train and export the model

Run the ETL notebook first so `customers` exists and holds the latest data. Then run all cells in `notebook/health_insurance_model.ipynb`, including the final **Export the trained model for the app** cell. That cell:

1. saves the complete fitted pipeline to `app/health_insurance_model.joblib`,
2. writes `app/model_metadata.json` with the F1-optimal threshold and validation metrics, and
3. reloads the model and checks that it reproduces the test-set probabilities.

The app shows an error and stops if `app/health_insurance_model.joblib` does not exist, so run the notebook before starting the app. If `model_metadata.json` is missing the app still runs but starts the threshold slider at 0.5.

Do not commit the `.joblib` artifact; it is regenerated by the notebook and is listed in `.gitignore`.

## Model inputs

The model uses the 10 customer features from the Kaggle dataset: gender, age, driving license (yes/no), region code (0-52), previously insured (yes/no), vehicle age (`< 1 Year`, `1-2 Year`, `> 2 Years`), vehicle damage (yes/no), annual premium, policy sales channel code, and vintage (days as a customer).

`id` is excluded because it identifies a row rather than describing a customer. There are no post-outcome columns in this dataset, so unlike the breast-cancer lab there is no target leakage to remove.

If you retrain with different columns, update the form fields and the `customer` DataFrame in `app/streamlit_app.py` to match.

## Validation results

The model notebook compares Logistic Regression, Random Forest and Hist Gradient Boosting (5-fold stratified CV on ROC-AUC), tunes the best one (Hist Gradient Boosting) with `RandomizedSearchCV`, and evaluates it on a 20% stratified validation split (`random_state=42`, 76,222 rows):

| Metric | Value |
|---|---|
| ROC-AUC (competition metric) | 0.858 |
| PR-AUC (average precision) | 0.367 |
| F1 at default 0.5 threshold | 0.003 |
| F1-optimal threshold | 0.217 |
| Precision at 0.217 | 0.33 |
| Recall at 0.217 | 0.78 |
| F1 at 0.217 | 0.461 |

Only ~12.3% of customers respond, so the default 0.5 cutoff predicts almost nobody as interested even though the ranking quality (ROC-AUC) is good. The app therefore defaults its decision threshold to the notebook's F1-optimal value and lets you move it: lower catches more responders at the cost of more wasted calls, higher is more selective. These numbers change if the data in MySQL changes.

The notebook then retrains on the full training set, scores `data/test.csv`, and writes `data/submission.csv` (`id`, `Response` = predicted probability, matching `sample_submission.csv`'s format).

## Run the app

From the project root:

```powershell
.venv\Scripts\python.exe -m streamlit run app/streamlit_app.py
```

Open the local URL printed by Streamlit, normally `http://localhost:8501`. Press `Ctrl+C` in that terminal to stop it.

## Troubleshooting

- `ModuleNotFoundError: No module named 'streamlit'` (or any other package): the wrong interpreter is active. Install with `.venv\Scripts\python.exe -m pip install -r app/requirements.txt` and run with `.venv\Scripts\python.exe -m streamlit ...`.
- `Can't connect to MySQL server on 'localhost'`: MySQL is not started in the XAMPP Control Panel. Only the notebooks need the database; the app reads the `.joblib` file and works without it.
- `No trained model found` in the app: run the model notebook through its export cell.
- The kernel dies during the baseline comparison or tuning cells: this machine has limited free RAM, which is why every estimator in the notebook uses `n_jobs=1`. Do not raise it.

## Important limitations

The app is an educational demonstration. Its output is a statistical model estimate of interest, not a decision. The probabilities are rankings, not calibrated frequencies; the operating threshold should be chosen from the real cost of a wasted call versus a missed sale, which this dataset does not contain. Before real-world use, the model would need cross-validated threshold selection, calibration, fairness review across gender and age, drift monitoring, privacy and security controls, and business review.
